Phần 2 / 3 — Embed Protocol & Cross-Window Communication

Đặc tả Kỹ thuật: Nhúng xINBOX Iframe & Giao thức postMessage Hai chiều

Mô tả đầy đủ kiến trúc nhúng ứng dụng xINBOX dưới dạng <iframe> vào bất kỳ hệ thống Web App nào: cấu hình quyền trình duyệt, whitelist bảo mật ALLOWED_ORIGINS, vòng đời xác thực SSO ngầm bằng User Mapping, hàng đợi chống Race Condition và hợp đồng window.postMessage hai chiều.

Không tìm thấy mục nào khớp từ khóa tìm kiếm.

1 Tổng quan Kiến trúc Nhúng <iframe>

1.1 Cấu hình Nhúng & Quyền Trình duyệt

Ứng dụng tích hợp nhúng trực tiếp giao diện xINBOX qua thẻ <iframe> trỏ tới URL triển khai của xINBOX Web (ví dụ: https://xinbox-lite.hub.vn/):

HTML — Iframe Embed Snippet 
<iframe
  src="https://xinbox-lite.hub.vn/"
  allow="autoplay; display-capture; microphone; camera; clipboard-read; clipboard-write"
  style="width: 100%; height: 100%; border: 0;"
></iframe>
  • Quyền Media & Clipboard: Thuộc tính allow cấp quyền phát âm thanh thông báo tin nhắn mới, ghi âm/gọi media, chụp màn hình và copy/paste nhanh.
  • Nếu có dùng sandbox: Phải mở đủ allow-same-origin allow-scripts allow-forms allow-modals allow-popups để không chặn script, form và popup OAuth.
  • Khuyến nghị giữ sống trong DOM (Persistent Mount): Nên ẩn/hiện bằng CSS khi đóng/mở thanh bên chứa xINBOX thay vì hủy (unmount) thẻ <iframe>. Điều này giúp giữ nguyên kết nối WebSocket realtime để hệ thống tích hợp nhận được thông báo số tin chưa đọc (OMNICHANNEL_UNREAD_COUNT_CHANGED) ngay cả khi khung chat đang đóng, đồng thời giúp lần mở lại tức thì không phải tải lại trang.

1.2 Điều kiện Tiên quyết về Origin & Whitelist Bảo mật

xINBOX Iframe kiểm tra nghiêm ngặt event.origin theo danh sách trắng (ALLOWED_ORIGINS) ở cả 2 chiều:

  1. Chiều nhận lệnh từ Host: Mọi postMessage từ event.origin không nằm trong whitelist đều bị xINBOX Iframe bỏ qua.
  2. Chiều gửi dữ liệu nhạy cảm lên Host: Các sự kiện chứa token xác thực (OMNICHANNEL_AUTH_CONNECTED, OMNICHANNEL_AUTH_COMPLETE) tuyệt đối không gửi tới wildcard "*". Nếu domain hệ thống tích hợp (lấy từ ancestorOrigins[0] hoặc document.referrer) chưa có trong whitelist phía xINBOX, xINBOX Iframe sẽ chặn gửi.

Yêu cầu triển khai: Trước khi tích hợp trên môi trường Staging/Production, đội vận hành phải đăng ký domain chính xác (bao gồm scheme + host + port nếu có, VD: https://app.company.com) của hệ thống tích hợp vào danh sách ALLOWED_ORIGINS của xINBOX Iframe.

2 Vòng đời Xác thực & Đồng bộ Trạng thái (Host ⟷ xINBOX Iframe)

2.1 Nguồn Dữ liệu Xác thực

Hệ thống tích hợp lấy bản ghi User Mapping của người dùng hiện tại từ Backend Nội bộ (tùy kiến trúc hệ thống tích hợp, có thể truy vấn theo cặp (workspaceId, userId) hoặc chỉ theo userId nếu không chia Workspace):

  • Ví dụ minh họa Response: { workspaceId?, hostUserId, xinboxAgentId, token, pubSubToken, isEnabled }
  • Lưu ý thiết kế Mapping phía Host: workspaceId không bắt buộc phải có. Nếu hệ thống tích hợp là Single-tenant hoặc mỗi user chỉ liên kết 1 tài khoản xINBOX duy nhất, Backend nội bộ có thể chỉ lưu theo hostUserId (bỏ qua hoặc đặt mặc định workspaceId = 0 / 1). xINBOX Iframe không dùng workspaceId này để xử lý nghiệp vụ chat (nghiệp vụ xINBOX chạy theo accountId).

2.2 Ba Trạng thái Khởi tạo Khi Mở / Chuyển Workspace

  1. Trạng thái A — Đã có Mapping kèm token hợp lệ (SSO Tự động): Khi <iframe> đã load hoặc phát OMNICHANNEL_READY và đã có token từ Backend Nội bộ, Host gửi OMNICHANNEL_INIT_AUTH chứa token tới đúng targetOrigin của xINBOX. xINBOX tự đăng nhập, mở WebSocket realtime, tải danh sách hội thoại rồi phát lại OMNICHANNEL_AUTH_COMPLETE.
  2. Trạng thái B — Đã có Mapping nhưng CHƯA có token: Host gửi OMNICHANNEL_LOGOUT để Iframe hiện form đăng nhập 1 lần (kèm gửi OMNICHANNEL_INIT_AUTH không token nếu muốn hiện Co-branding brandName). User đăng nhập xong → Iframe phát OMNICHANNEL_AUTH_CONNECTED → Host gọi updateUserMapping lưu bù token + pubSubToken.
  3. Trạng thái C — Chưa có Mapping trên Backend Nội bộ: Host gửi OMNICHANNEL_LOGOUT để hiện form đăng nhập. Khi user đăng nhập thành công và Iframe phát OMNICHANNEL_AUTH_CONNECTED, Host gọi createUserMapping để tạo liên kết mới.

Cơ chế Handshake khi Iframe khởi động: Khi mới nạp vào DOM mà chưa có phiên, xINBOX Iframe tự phát OMNICHANNEL_READY nhiều nhịp (0ms, 100ms, 300ms, 700ms, 1500ms) và chờ tối đa 3000ms để Host App bơm OMNICHANNEL_INIT_AUTH trước khi tự mở form đăng nhập thủ công.

Sơ đồ Tuần tự SSO & User Mapping

2.3 Xử lý Khi Chuyển Workspace hoặc Hết hạn Phiên

  • User đổi Workspace trên Hệ thống Tích hợp: Đặt lại cờ hasInjectedAuth = false, xóa trạng thái tạm, gọi lại getMyMapping(newWorkspaceId) (bỏ qua cache) rồi thực hiện lại theo 1 trong 3 trạng thái ở Mục 2.2.
  • Token hết hạn (401 Unauthorized từ xINBOX Server): xINBOX Iframe tự ngắt WebSocket, logout và phát lại OMNICHANNEL_READY.
  • User tự bấm Đăng xuất trong Iframe: Iframe gửi OMNICHANNEL_LOGOUT về Host → Host xóa cache mapping cục bộ (giữ ghi nhớ hasExistingMappingOnServer để lần login lại gọi update).
  • User bấm Hủy liên kết tài khoản trong Iframe: Iframe gửi OMNICHANNEL_DELETE_MAPPING → Host gọi API nội bộ deleteUserMapping, xóa state cục bộ và gửi OMNICHANNEL_LOGOUT vào Iframe.

3 Đặc tả Giao thức window.postMessage Hai chiều

JSON — Định dạng gói tin chuẩn 
{
  "type": "<EVENT_TYPE>",
  "payload": { }
}

Lưu ý: Luôn truyền JSON thuần (tránh Proxy/Reactive object gây DataCloneError). Các tên type (OMNICHANNEL_INIT_AUTH, OMNICHANNEL_READY...) là chuỗi định danh cố định trên đường truyền giữa hai ứng dụng.

3.1 Chiều Host App ➔ xINBOX Iframe

Event type Alias hỗ trợ Cấu trúc payload Mục đích & Hành vi phía xINBOX Iframe
OMNICHANNEL_INIT_AUTH INIT_AUTH, SET_AUTH, OMNICHANNEL_SET_TOKEN { token?, pubsubToken?, userId?, workspaceId?, deletedUserId?, brandName?, externalViewImage?, externalContact?, showToggleSize? } Bơm User Access Token để tự động đăng nhập (hoặc truyền cấu hình Co-branding brandName & 3 cờ UI ngay cả khi chưa có token). Nếu có token, Iframe trả OMNICHANNEL_AUTH_COMPLETE; nếu không có token, Iframe tắt loading và mở ngay form đăng nhập Co-branding.
OMNICHANNEL_LOGOUT LOGOUT {} Ép đăng xuất phiên hiện tại, ngắt WebSocket realtime và hiển thị form đăng nhập.
OMNICHANNEL_SWITCH_WORKSPACE SWITCH_WORKSPACE { accountId } (hoặc số) Chuyển tài khoản/workspace xINBOX đang active sang accountId (tự đợi tối đa 6s nếu đang auth).
OMNICHANNEL_OPEN_CONVERSATION — { conversationId, accountId? } Đợi auth sẵn sàng → chuyển sang accountId (nếu có và khác hiện tại) → mở đúng phòng chat conversationId.
OMNICHANNEL_OPEN_NEW_CONVERSATION — { contact?, accountId? } Đợi auth → chuyển accountId → mở Modal soạn hội thoại mới kèm điền sẵn contact.
OMNICHANNEL_CONTACT_DELETED — { contactId, accountId? } Đồng bộ xóa từ CRM Host: lọc bỏ hội thoại của contactId, đóng chi tiết nếu đang mở và tải lại danh sách.
OMNICHANNEL_SIZE_CHANGED — { size: string, isFull: boolean } Báo trạng thái kích thước khung chứa (thường vs "FULL") để header trong Iframe đồng bộ nút phóng to/thu nhỏ.
OMNICHANNEL_LANG_CHANGE SET_LANG { lang: "vi" | "en" } (hoặc locale) Đồng bộ thay đổi ngôn ngữ hiển thị trong Iframe theo Host App.

3.2 Chiều xINBOX Iframe ➔ Host App

Event type Cấu trúc payload Mục đích & Hành vi phía Host App
OMNICHANNEL_READY { status: "ready" } Iframe sẵn sàng nhận lệnh. Host trả OMNICHANNEL_SIZE_CHANGED và bơm OMNICHANNEL_INIT_AUTH (nếu có token chưa inject), hoặc flush pendingAction.
OMNICHANNEL_AUTH_COMPLETE { status: "complete" } Xác thực & tải xong hội thoại ban đầu. Đây là tín hiệu chuẩn nhất để Host App thực thi pendingAction.
OMNICHANNEL_AUTH_CONNECTED { id, token, pubsubToken, accountId, accounts, user? } User đăng nhập thủ công thành công trong Iframe. Host gọi createUserMapping / updateUserMapping lưu phiên. (Chỉ gửi tới origin trong ALLOWED_ORIGINS).
OMNICHANNEL_LOGOUT {} User bấm Đăng xuất trong Iframe → Host xóa cache phiên cục bộ.
OMNICHANNEL_DELETE_MAPPING { workspaceId?, deletedUserId? } User bấm Hủy liên kết trong Iframe → Host gọi deleteUserMapping, dọn state và gửi lại OMNICHANNEL_LOGOUT.
OMNICHANNEL_UNREAD_COUNT_CHANGED { unreadCount, hasUnread, latestMessage? } Phát tự động khi tổng tin chưa đọc đổi → Host cập nhật badge/chấm đỏ (ngay cả khi Iframe đang ẩn).
OMNICHANNEL_TOGGLE_SIZE legacy: fullsizePopup { isFull: boolean } User bấm nút phóng to/thu nhỏ trên Header Iframe → Host đổi kích thước khung chứa (thường ↔ "FULL") và lưu tùy chọn.
OMNICHANNEL_GET_SIZE {} Iframe hỏi kích thước hiện tại khi header mount → Host gửi lại OMNICHANNEL_SIZE_CHANGED.
OMNICHANNEL_CONTACT_DELETED { contactId, accountId? } User xóa Contact trong Iframe → Host đồng bộ xóa/cập nhật danh sách Contact trên CRM.
OMNICHANNEL_VIEW_CONTACT externalContact: true { contactId, accountId?, conversationId?, contact? } User bấm "Xem thông tin liên hệ" (tùy chọn riêng trong menu ...) → Host nhận contactId để tự gọi API và mở hồ sơ CRM bên Host.
OMNICHANNEL_VIEW_IMAGE legacy: viewListImage { index: number, images: Array<{ title, url, thumbUrl? }> } Khi externalViewImage: true: Host bật Lightbox toàn màn hình (chỉ nghe OMNICHANNEL_VIEW_IMAGE để tránh mở 2 lần). Khi false: Iframe tự mở viewer nội bộ.

4 Hàng đợi Hành động, Chống Race Condition & Tùy biến UI

4.1 Cơ chế Hàng đợi Hành động (Pending Action Queue)

  • Capture ở tầng Global trước khi Mount: Đăng ký listener cấp ứng dụng (global singleton) giữ hành động gần nhất (pendingOpenAction = { type, payload }) ngay cả trước khi thẻ <iframe> mount vào DOM.
  • Điều kiện đẩy lệnh ngay (dispatchActionToIframe): Chỉ gửi trực tiếp khi đồng thời đạt iframe có trong DOM, iframeLoaded === true và hasInjectedAuth === true; nếu chưa → giữ trong pendingOpenAction.
  • Flush & Retry an toàn: Trigger chính tại OMNICHANNEL_AUTH_COMPLETE; fallback timer 500ms sau khi gửi OMNICHANNEL_INIT_AUTH; retry tối đa 20 lần × 200ms (4s) rồi hủy để tránh treo vòng lặp.

4.2 Chống Race Condition khi Chuyển Workspace & Mở Hội thoại

Tuyệt đối không gửi OMNICHANNEL_SWITCH_WORKSPACE tách rời song song với OMNICHANNEL_OPEN_CONVERSATION. Thay vào đó, luôn gói accountId nằm ngay bên trong payload của OMNICHANNEL_OPEN_CONVERSATION (hoặc OMNICHANNEL_OPEN_NEW_CONVERSATION) để Iframe tự await chuyển workspace xong rồi mới mở hội thoại.

4.3 Bảo mật postMessage Hai phía

  • Khi nhận: Luôn phân tích expectedOrigin = new URL(xinboxIframeUrl).origin và kiểm tra if (event.origin !== expectedOrigin) return;.
  • Khi gửi: Luôn truyền đúng targetOrigin = new URL(xinboxIframeUrl).origin thay vì "*" cho mọi gói tin chứa token/dữ liệu.
  • Nếu truyền token qua URL Query: Iframe tự xóa token khỏi thanh địa chỉ bằng history.replaceState, nhưng vẫn khuyến nghị dùng postMessage (OMNICHANNEL_INIT_AUTH).

4.4 Cơ chế Đồng bộ Nút Toggle Resize & Ngưỡng Responsive 1/2/3 Cột

4.5 Tùy chọn externalViewImage & externalContact

  • externalViewImage (mặc định false): false → mở viewer nội bộ trong Iframe; true → phát OMNICHANNEL_VIEW_IMAGE (kèm legacy viewListImage) để Host mở Lightbox toàn màn hình.
  • externalContact (mặc định false): Tùy chọn tách riêng hoàn toàn (không liên quan tới panel "Thông tin hội thoại" nội bộ). Khi true, menu ... của hội thoại hiện thêm mục "Xem thông tin liên hệ" trên mọi kích thước màn hình; bấm vào sẽ emit OMNICHANNEL_VIEW_CONTACT kèm { contactId, accountId?, conversationId?, contact? } để Host tự gọi API và mở giao diện hồ sơ riêng.

5 Checklist Triển khai cho Hệ thống Độc lập

  1. Đăng ký Whitelist: Gửi domain Staging & Production của Host để cấu hình vào ALLOWED_ORIGINS phía xINBOX Iframe.
  2. Dựng Khung Nhúng Persistent: Nhúng <iframe src="https://xinbox-lite.hub.vn/" allow="...">, chỉ ẩn/hiện bằng CSS để duy trì WebSocket nhận OMNICHANNEL_UNREAD_COUNT_CHANGED.
  3. Nối API Mapping & Init Payload: Gọi getMyMapping → bơm OMNICHANNEL_INIT_AUTH kèm brandName và 3 cờ (externalViewImage, externalContact, showToggleSize) hoặc gửi OMNICHANNEL_LOGOUT + config không token khi chưa đăng nhập; đồng bộ OMNICHANNEL_AUTH_CONNECTED, OMNICHANNEL_LOGOUT, OMNICHANNEL_DELETE_MAPPING.
  4. Hàng đợi & Đồng bộ UI hai chiều: Cài pendingOpenAction flush tại OMNICHANNEL_AUTH_COMPLETE; bắt OMNICHANNEL_TOGGLE_SIZE, OMNICHANNEL_GET_SIZE, OMNICHANNEL_VIEW_IMAGE, OMNICHANNEL_VIEW_CONTACT và đồng bộ OMNICHANNEL_CONTACT_DELETED.
  5. Kiểm tra Origin hai đầu: Xác thực event.origin === new URL(xinboxUrl).origin khi nhận và truyền đúng targetOrigin khi gửi.
