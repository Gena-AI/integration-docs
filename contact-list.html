Đặc tả Kỹ thuật: Danh sách & Quản lý Liên hệ (Contacts API)

Dành cho đội ngũ phát triển Ứng dụng Di động (Mobile App iOS / Android) và Nền tảng Tích hợp CRM. Tài liệu chuẩn hóa toàn bộ luồng nạp dữ liệu, phân trang, tìm kiếm, lọc nâng cao, cấu trúc trường hiển thị, ánh xạ nhân viên & doanh nghiệp, kéo thả Kanban và các thao tác liên quan đến Liên hệ.

1 Kiến trúc & Xác thực (Architecture & Auth)

Mọi truy vấn danh bạ liên hệ đều đi qua xINBOX Gateway và gắn chặt với định danh tài khoản con (accountId):

MụcGiá trị
Base URLhttps://xinbox-app.hub.vn (hoặc domain cấu hình theo môi trường)
api_access_tokenToken người dùng xINBOX (gửi trong Header request)
Content-Typeapplication/json
Cấu trúc URL/api/v1/accounts/{accountId}/contacts...
Lưu ý cho App Mobile: Khi người dùng chuyển đổi Workspace / Tài khoản xINBOX, App bắt buộc phải xóa sạch cache danh bạ cũ và kích hoạt lại quy trình nạp từ Trang 1 của accountId mới.

2 Quy trình Khởi tạo Dữ liệu (Initialization Sequence)

Trước khi render danh sách liên hệ lên màn hình, App cần thực hiện 4 bước khởi tạo nền tảng:

  1. Bước 1: Lấy activeAccountId & Token: Xác định tài khoản đang làm việc từ phiên đăng nhập.
  2. Bước 2: Nạp Danh mục Nhân viên (Agents): Gọi GET /api/v1/accounts/{accountId}/agents để lưu map từ id sang Tên hiển thị, Email và Avatar của nhân viên phụ trách.
  3. Bước 3: Nạp Định nghĩa Trường tùy chỉnh (Custom Fields): Gọi GET /api/v1/accounts/{accountId}/custom_attribute_definitions?attribute_model=1 để biết danh mục các trường động của Contact.
  4. Bước 4: Nạp Cấu hình Bộ lọc Đã lưu (Saved Views): Gọi GET /api/v1/accounts/{accountId}/custom_filters?filter_type=1 để hiển thị các Tab lọc (Tất cả, Của tôi, Chưa phân công và các Tab riêng).
  5. Bước 5: Nạp Danh sách Liên hệ Trang 1: Gọi GET /api/v1/accounts/{accountId}/contacts?page=1 để hiển thị dữ liệu ban đầu.

5 Lưu ý Đặc biệt: Xử lý lead_status và assigned_agent

Đây là 2 thuộc tính quan trọng bậc nhất trong CRM nhưng có cơ chế lưu trữ và xử lý đặc thù mà đội App bắt buộc phải nắm rõ để tránh lỗi giao diện, sai lệch trạng thái hoặc mất liên kết nhân viên.

⚠️

5.1 Bản chất Lưu trữ: Nằm trong custom_attributes (Không phải Root Field)

Trong kiến trúc xINBOX CRM, model Contact không có cột trực tiếp tên là lead_status hay assigned_agent ở cấp root (như name, email, phone_number). Cả 2 trường này nằm trong object custom_attributes:

  • contact.custom_attributes.lead_status
  • contact.custom_attributes.assigned_agent (hoặc fallback contact.additional_attributes.assigned_agent ở bản ghi cũ).

Quy tắc ghi (POST / PATCH): Payload gửi lên bắt buộc phải bọc trong custom_attributes: { "custom_attributes": { "lead_status": "contacted", "assigned_agent": 82 } }. Tuyệt đối không để ngoài root payload vì API sẽ bỏ qua.

5.2 Chuyên sâu về lead_status (Trạng thái Lead & Legacy Values)

Hệ thống có 5 trạng thái chuẩn quốc tế. Tuy nhiên, do dữ liệu từ nhiều nguồn (import Excel, bot webhook, dữ liệu cũ), database tồn tại các giá trị kế thừa (Legacy Values) bằng tiếng Việt hoặc tiếng Anh.

Khách mới phát sinh, chưa có tương tác từ nhân viên.

contactedĐang tư vấn

Đã ký hợp đồng hoặc chuyển đổi đơn hàng.

Khách hủy nhu cầu hoặc không đạt tiêu chí.

Quy tắc Bắt buộc cho App khi xử lý lead_status:

  • Khi Đọc dữ liệu (GET list / search / filter): BẮT BUỘC chạy qua hàm normalizeLeadStatus(val) để quy về key chuẩn trước khi so sánh logic hoặc đưa vào cột Kanban. Tuyệt đối không so sánh trực tiếp chuỗi dạng status === "contacted".
  • Khi Ghi dữ liệu (PATCH / POST / Kéo thả Kanban): LUÔN LUÔN ghi key chuẩn quốc tế: "new", "contacted", "qualified", "won", "lost". CẤM ghi chuỗi tiếng Việt. Kéo vào Chưa có trạng thái gửi null.
TypeScript / Dart Normalizer 
// Hàm chuẩn hóa Lead Status trên App Client
export function normalizeLeadStatus(val?: string | null): string {
  if (!val || typeof val !== 'string') return '';
  const trimmed = val.trim();
  if (!trimmed || trimmed === '__unassigned__') return '';

  const lower = trimmed.toLowerCase();
  if (['new', 'moi_tiep_can', 'mới tiếp cận'].includes(lower)) return 'new';
  if (['contacted', 'dang_tu_van', 'đang tư vấn', 'consulting', 'in_progress'].includes(lower)) return 'contacted';
  if (['qualified', 'tiem_nang', 'tiềm năng'].includes(lower)) return 'qualified';
  if (['won', 'thanh_cong', 'thành công', 'customer', 'converted'].includes(lower)) return 'won';
  if (['lost', 'that_bai', 'thất bại', 'unqualified'].includes(lower)) return 'lost';

  return trimmed; // fallback nếu có custom status mới
}

5.3 Chuyên sâu về assigned_agent (Nhân viên Phụ trách & Lookup ID)

Trường assigned_agent chỉ lưu số nguyên ID nhân viên (ví dụ: 82), hoàn toàn không chứa thông tin Họ tên hay Avatar. API Contact cũng không tự JOIN thông tin user.

B1
Cache Master Data Agents trước: Khi khởi chạy CRM, gọi ngay GET /api/v1/accounts/{accountId}/agents và lưu vào RAM dạng Dictionary/Map: Map<number, Agent>.
B2
Tra cứu khi render: Lấy agentId = contact.custom_attributes?.assigned_agent. Nếu có ID, tra trong Map để hiển thị tên và avatar. Nếu rỗng hoặc null, hiển thị nhãn "Chưa phân công".
B3
Gán & Bỏ gán nhân viên: Gọi PATCH /contacts/{id} với { "custom_attributes": { "assigned_agent": 82 } }. Khi hủy phân công, gửi { "custom_attributes": { "assigned_agent": null } }.

Trên App khi người dùng chọn tab hệ thống, gửi request POST /api/v1/accounts/{accountId}/contacts/filter với điều kiện sau:

}

6 Hướng dẫn Triển khai cho Mobile App

6.1. Cuộn vô tận (Infinite Scroll) & Kéo để làm mới (Pull-to-refresh)

  • Khởi tạo luôn nạp page = 1.
  • Khi cuộn tới 80% danh sách: kiểm tra hasMore = contacts.length < meta.count. Nếu còn dữ liệu thì tăng page += 1 và tải tiếp để nối mảng.
  • Kéo vuốt làm mới (Pull-to-refresh): gọi lại page = 1 và thay thế toàn bộ dữ liệu.

6.2. Hỗ trợ 2 Chế độ hiển thị: List View & Kanban View

  • Chế độ Danh sách: Hiển thị thẻ tóm tắt (Avatar, Tên, Số điện thoại, Tag Trạng thái, Doanh nghiệp).
  • Chế độ Phễu Kanban: Phân theo 5 cột trạng thái Lead. Khi kéo thả thẻ sang cột khác, áp dụng cơ chế Optimistic Update (cập nhật UI ngay lập tức rồi gửi API PATCH ngầm). Nếu API lỗi thì hoàn tác vị trí thẻ và bắn thông báo Toast lỗi.

6.3. Thao tác Quẹt Nhanh trên Danh sách (Swipe Gestures)

  • Quẹt sang phải: Kích hoạt gọi điện thoại nhanh (tel:) hoặc gửi tin nhắn Zalo/SMS.
  • Quẹt sang trái: Mở nhanh menu tùy chọn: Phân công nhân viên, Đổi trạng thái Lead, Xem chi tiết hoặc Xóa liên hệ.
