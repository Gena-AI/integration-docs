Phần 1 / 3 — Multi-Gateway API, User Mapping DB & Admin Governance

Đặc tả Kiến trúc & API: Module Quản trị Tích hợp xINBOX

Mô tả đầy đủ kiến trúc 2 khối Backend (xINBOX Gateway + API Nội bộ Hệ thống Tích hợp), cơ chế xác thực, vòng đời trạng thái kết nối, hợp đồng HTTP/JSON chi tiết, schema bảng Mapping, quy tắc nghiệp vụ và hành vi giao diện của Module Quản trị Tích hợp xINBOX.

Không tìm thấy mục nào khớp từ khóa tìm kiếm.

1 Tổng quan Kiến trúc & Xác thực

1.1 Mô hình Kiến trúc Hai Khối (xINBOX Gateway + API Nội bộ Hệ thống Tích hợp)

Khối API Chủ sở hữu Vai trò nghiệp vụ Ví dụ Prefix / Gateway
1. xINBOX Gateway API (Chuẩn cố định) xINBOX Server Xác thực phiên xINBOX, lấy danh sách Workspace/Account & hạn mức gói, quản trị Agent, Kênh chat (Inboxes), Nhãn & Nhóm nhãn, Tin nhắn mẫu, Trường tùy chỉnh và Kết nối lại kênh /api-xinbox ➔ xINBOX Server
2. API Nội bộ Hệ thống Tích hợp (Đội Dev tự xây) Backend Hệ thống Tích hợp Gồm 2 dịch vụ nội bộ: (1) Trả danh sách thành viên Workspace; (2) Lưu bảng ánh xạ 1-1 giữa nhân sự nội bộ và Agent xINBOX (kèm token phiên kết nối) Nội bộ (VD /api-core, /api-internal)

Hạ tầng Reverse Proxy: Nếu Frontend gọi qua proxy cùng domain để tránh CORS, cấu hình timeout tối thiểu 60s, giới hạn payload tối đa 50MB, và kiểm tra origin/referer hợp lệ cho gateway /api-xinbox/.

1.2 Authentication & Headers

Header (Cổng xINBOX) Bắt buộc Giá trị / Quy tắc xử lý phía Backend
api_access_token (hoặc api_key) Có (trừ sign_in) Truyền 1 token duy nhất:
• Account API Key (tiền tố xib_...): Chỉ dùng cho endpoint /api/v1/accounts/{accountId}/... khớp đúng workspace cấp key. Gọi /api/v1/profile hoặc workspace khác sẽ trả 401 Unauthorized.
• User Access Token (không tiền tố xib_): Bắt buộc dùng cho màn hình Quản trị Tích hợp để gọi /api/v1/profile, liệt kê toàn bộ Account, kiểm tra quyền administrator và chuyển qua lại giữa các Workspace.
Content-Type Có application/json

Với API Nội bộ của Hệ thống Tích hợp: Dùng sẵn cơ chế phiên đăng nhập của hệ thống tích hợp (Authorization: Bearer <session_token> hoặc Cookie/Session), kiểm tra caller là thành viên / Admin hợp lệ trước khi đọc ghi User Mapping.

2 Đầu vào Ngữ cảnh & 5 Luồng Kết nối Chính

2.1 Tham số Ngữ cảnh Đầu vào

  1. currentWorkspaceId (Number — Bắt buộc): ID Workspace hiện hành trên hệ thống tích hợp để cô lập dữ liệu mapping & lựa chọn Account cục bộ.

    Hệ thống không chia Workspace: xINBOX chạy nghiệp vụ theo selectedAccountId, không dùng currentWorkspaceId. Hệ thống Single-tenant có thể gán cố định currentWorkspaceId = 1 (hoặc 0), hoặc bỏ hẳn cột workspace_id trong DB nội bộ và khóa duy nhất theo host_user_id. Nếu chia theo Công ty/Chi nhánh, map vào companyId / organizationId.

  2. currentUserId (Number — Bắt buộc): ID quản trị viên đang đăng nhập hệ thống tích hợp — đối chiếu quyền sở hữu bản ghi User Mapping.
  3. selectedAccountId (Number — Động): ID Workspace/Account bên phía xINBOX, định tuyến toàn bộ API /api/v1/accounts/{accountId}/..., lưu local theo khóa __xinbox_account_{currentWorkspaceId}.

2.2 Vòng đời Trạng thái & 5 Luồng Vận hành

  • Luồng 1 — Card Tổng quan Tích hợp: Gọi listWorkspaceMappings → đếm mappedCount các nhân sự có Agent ID hợp lệ → tìm mapping của currentUserId; trạng thái Đang hoạt động khi có mapping + Agent ID hợp lệ + isEnabled !== false.
  • Luồng 2 — Khởi tạo Trang Chi tiết (checkInitialConnection): Reset state → gọi getMyMapping → kiểm tra đủ 4 điều kiện (có dữ liệu; hostUserId == currentUserId; xinboxAgentId > 0; token khác rỗng). Khi đạt: gọi GET /api/v1/profile, khôi phục selectedAccountId, tải song song 5 nhóm (Account detail, Ghép nối nhân sự, Inboxes, Labels, Canned Responses) và lazy-load inbox_members / custom_attribute_definitions theo Tab.
  • Luồng 3 — Kết nối Mới / Đăng nhập lại: Hỗ trợ Email + Mật khẩu (POST /auth/sign_in) hoặc User Access Token (GET /api/v1/profile). Kiểm tra bắt buộc accounts[] có ít nhất 1 Workspace giữ role "administrator"/"admin"; nếu thiếu quyền Admin → cảnh báo và dừng, không lưu mapping. Lưu xong chọn Account admin đầu tiên và tải dữ liệu.
  • Luồng 4 — Đổi Workspace xINBOX (selectedAccountId): Lưu local storage __xinbox_account_{currentWorkspaceId} → tải song song Account detail, Agents, Inboxes, Labels, Canned Responses (+ Custom Fields cả 3 scope nếu đang mở Tab).
  • Luồng 5 — Ngắt kết nối Toàn bộ (Disconnect): Mở Modal xác nhận mã bảo mật 6 chữ số ngẫu nhiên (100000–999999) → gọi deleteUserMapping cho currentUserId → xóa khóa local storage → reset isConnected = false.

3.1.4 Đặc tả Thiết kế Backend Nội bộ Hệ thống Tích hợp (Thành viên & User Mapping)

A. API Lấy Danh sách Thành viên Workspace: Input tối thiểu workspaceId → Output tối thiểu { userId, fullName, userName, email, avatar, roleId }.

B. Bảng DB Lưu Ánh xạ (user_xinbox_mappings) — Unique Constraint: (workspace_id, host_user_id):

C. 4 API Mapping Nội bộ & Quy tắc Phân quyền:

  1. getMyMapping: Input { workspaceId } (user từ session). Quyền: thành viên hợp lệ của workspaceId. Output: { workspaceId, hostUserId, xinboxAgentId, token, pubSubToken, isEnabled } hoặc null.
  2. listWorkspaceMappings: Input { workspaceId }. Quyền: Admin của workspaceId. Output mảng { workspaceId, hostUserId, xinboxAgentId, isEnabled, createdAt, updatedAt } — tuyệt đối KHÔNG trả token và pubSubToken của nhân sự khác.
  3. createUserMapping / updateUserMapping (hoặc upsertMapping): Input { workspaceId, targetUserId, xinboxAgentId, token?, pubSubToken?, isEnabled }. Quyền: targetUserId thuộc workspace; nếu targetUserId !== currentUserId bắt buộc caller là Admin. Upsert theo (workspace_id, targetUserId).
  4. deleteUserMapping: Input { workspaceId, deletedUserId }. Quyền: nếu deletedUserId !== currentUserId bắt buộc caller là Admin. Xóa bản ghi khỏi DB.

4 Quy tắc Nghiệp vụ, Cơ chế Polling & Xử lý Lỗi

4.1 Bảo mật & Phân quyền Agent

  • Super Admin (agent.id === 1): Khóa hoàn toàn mọi thao tác sửa, đổi mật khẩu, chuyển quyền sở hữu, xóa.
  • Chủ Workspace (agent.is_owner === true): Chỉ sửa name, khóa vai trò Quản trị viên, cấm đặt lại mật khẩu và cấm xóa.
  • Chuyển giao quyền Chủ Workspace: Chỉ bật cho Agent có role === "administrator", confirmed !== false, chưa phải is_owner.
  • Chính sách Mật khẩu Mạnh: Tối thiểu 8 ký tự, có ít nhất 1 chữ hoa (A-Z), 1 chữ thường (a-z), 1 ký tự đặc biệt. Bộ sinh ngẫu nhiên mặc định 12 ký tự trộn đủ 4 nhóm (số 2-9 tránh nhầm 0/1/O/l/I) bằng Fisher-Yates shuffle.

4.2 Ghép nối Nhân sự (Staff ↔ Agent Mapping)

  • Khớp email 1 chạm: Nếu agents[] đã có Agent trùng email (trim + lowercase) → hiện nút Ghép nối gọi thẳng createUserMapping; chưa có → nút Tạo điền sẵn name/email rồi map ngay sau khi tạo.
  • Foreign Agent Warning: Thành viên có xinboxAgentId không tồn tại trong agents[] của selectedAccountId hiện tại → hiện cảnh báo vàng "Đã map ở workspace khác" kèm ID: #{agentId}.
  • Bulk Quick-Create & Map: Dùng 1 mật khẩu chung hợp lệ kiểm tra với agentLimit, chạy tuần tự từng nhân sự; nếu API trả lỗi "already" / "taken" / "exist", tự gọi lại GET .../agents tìm email khớp và map luôn.
  • Unmap 1 nhân sự: Yêu cầu mã xác nhận 4 chữ số (1000–9999). Nếu tự unmap chính currentUserId → xóa cache và reset isConnected = false.

4.3 Cơ chế Polling Kết nối lại Zalo QR

Tải ảnh qr_image_base64 → chạy timer polling mỗi 3000ms (3 giây) gọi .../status (bỏ qua lỗi mạng thoáng qua). Dừng ngay bằng clearInterval khi: (1) connected → tải lại Inboxes và tự đóng Modal sau 1800ms; (2) expired / logged_out → hiện nút Làm mới QR; (3) User đóng Modal hoặc rời màn hình.

4.4 Quy tắc Kênh chat, Nhãn, Mẫu tin nhắn & Trường tùy chỉnh

  • Kênh mất kết nối: reauthorization_required === true kích hoạt chấm nhấp nháy & định tuyến Zalo QR / Email (tab oauth hoặc imap_smtp) / Social OAuth popup 600x700.
  • Nhãn: Chuẩn hóa title chữ thường, khoảng trắng → _, gộp nhiều _, tối đa 50 ký tự; optimistic toggle show_on_sidebar; kéo-thả reorder chỉ bật khi không search & không lọc nhóm.
  • Mẫu tin nhắn: Cắt khoảng trắng & dấu / đầu short_code (max 50 ký tự; content max 1000 ký tự).
  • Trường Tùy chỉnh & System Default Fields (Cấm Sửa & Cấm Xóa): Prefetch song song cả 3 scope; auto-slug Unicode NFD bỏ dấu khi tạo mới; xóa yêu cầu mã bảo mật 6 chữ số (100000–999999). Trường hệ thống bảo vệ: Scope 1 (assigned_agent, lead_status); Scope 2 (address, tax_code, industry, company_phone).

4.5 Chuẩn hóa Xử lý Lỗi

  1. HTTP 401 / 403: sign_in báo sai thông tin; /profile báo User Access Token hết hạn/truyền nhầm key xib_...; endpoint account báo cần quyền Administrator nếu thông điệp chứa "authorized".
  2. HTTP 402 hoặc lỗi chứa "limit exceeded" / "license" / "purchase more": Báo chạm hạn mức gói (Agents hoặc Inboxes).
  3. Validation data.errors: Mảng nối ", "; object format "field: msg1, msg2; ...".

5 Checklist Triển khai cho Hệ thống Độc lập

  1. Dựng proxy cổng xINBOX + bảng DB user_xinbox_mappings + 4 API Mapping nội bộ (ẩn token ở listWorkspaceMappings), dùng User Access Token cho luồng Admin.
  2. Triển khai đủ 4 điều kiện ở checkInitialConnection và kiểm tra bắt buộc ít nhất 1 Workspace có quyền administrator trước khi lưu Mapping.
  3. Xử lý Foreign Agent Warning, check_email trùng toàn hệ thống, chính sách mật khẩu mạnh và fallback bulk create.
  4. Lazy-load inbox_members theo tab, định tuyến 6 nhóm kênh reconnect (Zalo QR poll 3s + cleanup, Email OAuth/IMAP, IG/TikTok/WA popup, Facebook callback).
  5. Khóa chặt System Fields, bất biến attribute_key/display_type, và hộp thoại mã xác nhận (4 số cho Unmap, 6 số cho Disconnect & Xóa Custom Field).
